# 次に進めること

最初に0〜30分の解析を1回実行し、入力区間と映像情報の抽出品質を評価します。全編の自動処理へ広げる前に、今回の結果を学習資料として使える状態にすることを優先します。

## 1. ご自身のターミナルで初回実行

```bash
cd /Users/nematatu/src/github.com/nematatu/learn-vite-conf
bash scripts/run-first-30m.sh --dry-run
bash scripts/run-first-30m.sh
```

キーは非表示入力です。チャットへ貼らないでください。成功時には実測値がメタデータへ出力されます。APIが失敗したらHTTP・ローカルのエラー・使用枠を確認し、モデルや方式を無断変更しません。タイムアウト時も再送前に処理・課金の可能性を確認します。

## 2. 結果を検証し、登壇ごとに整理

[品質検証票](quality-review.md)に沿って、話者の境界、スライド、コード、デモ、数値を照合します。特に利用者報告の600〜620秒のスライドを今回の記述と比較すると、20秒テストと30分テストの整合を調べる手がかりになります。ただし、同じモデルが同じ内容を返すだけでは映像の裏取りになりません。

登壇境界を確認できたらEvan Youのノートを分けます。WelcomeやChristoph Nakazawaの内容を混ぜず、技術的な理由・コード・図表・時刻・不明点を維持します。生成本文は原本として残し、修正内容はGit差分と検証票で追跡します。

## 3. 確認した成果物を公開

READMEの「未実行」を実際の結果へ変更し、ノート索引を実ファイルへリンクします。引用範囲・未確認事項をレビューした後、存在するファイルだけを明示してコミットします。

```bash
git status --short
git add notes/first-30-minutes.md notes/first-30-minutes.metadata.json
git add README.md notes/README.md docs/quality-review.md
git diff --cached --stat
git diff --cached --check
git diff --cached
git commit -m "docs: add reviewed first 30 minutes analysis"
git push origin main
```

登壇別ノートが完成した場合は、そのファイルも個別に `git add` してください。`.local/`、生レスポンス、ログ、キーは追加しません。

## 4. その後の進め方

- **情報が不足した場合**：不足した場面と理由、候補となる短区間、予想される追加利用を整理してから追加解析を判断します。自動再送しません。
- **次の登壇へ進む場合**：公式予定ではなく、確認したアーカイブ内の開始・終了から区間を決めます。現在の1800秒以内の制約を明示的に改訂し、1登壇ずつ品質・使用量を評価します。
- **技術学習**：レポート内のAPI・コードを各プロジェクトの公式文書と照合し、動画の主張と現在の仕様を分けて記録します。未確認の技術名から学習計画を確定しません。
- **方式の見直し**：`videoMetadata`の非推奨対応は別実験として扱い、仕様と短い同一区間の結果を比較します。初回の実装へ混ぜません。
- **NotebookLMへの活用**：検証したノートが揃ってから手動でソース化を検討します。今回の実装には含めません。
